## 实现与恢复边界

1. `PersonalScope` 每次实际读取/执行核对当前原生归属、原 cwd、归档状态。撤出项目或 cwd 改变即拒绝；归档/目录不存在拒绝新领取和执行。
2. `RolloutHistory` 只读原生 session JSONL/zstd；混合旧格式和新 canonical turn 按 turn 选择，保留原文字、工具顺序和原 ID，不加载视图或取消归档。大文件分块解析，选中会话增量读追加记录；只缓存两个选中历史。
3. 上传 Base64/图片二进制正文省略，过长工具详情明确展示首尾摘要（约 8 KiB 字符级边界）；聊天正文保留。这是文字/工具记录接入，不承诺手机保存完整附件或完整巨量工具日志。
4. 原生 `DesktopStream` 只跟随已加载 owner，同步公开增量、工具和审批；未加载/归档/目录缺失仍可使用文件历史。快照模式标注“历史已同步”，没有伪造逐 token 流。手机读历史不会为了获取 owner 自动打开桌面窗口。
5. `PersonalQueue` 按需创建 Inbox，避免启动时创建/恢复数百个空 SQLite。接收器仅处理实际存在的本服务 Inbox；未知/已租赁任务不重放。当前版本原生队列的 schema/migrations 精确匹配后，使用持久回执与原子 INSERT 追加控制消息，由 Codex 自己在空闲时执行。没有第二模型执行器，没有 native start/steer/interrupt。
6. 手机发送时普通原生 URL 只加载对应原会话，可能切换桌面显示；已有模型 turn 不被中断。只读查看归档不调用此入口。
7. 全局 `rmtcdx_mobile` 已配置，没有全局 MCP 热加载或桌面重启。新恢复的历史能加载新 MCP；缓存旧工具集的会话可使用 `mobile-queue-tool.mjs` 普通命令兼容入口，其调用绑定环境中的原生会话 ID、持久 UserMessage.client_id 和当前 inProgress turn，不接受任意 turn/runtime 参数；仍受本会话沙箱和正常审批约束。日志/手机投影移除队列租约凭据与兼容命令参数。
8. 独立 LaunchAgent `com.liutianwei.rmtcdx-personal-projects` 常驻。服务仅在手机有消息时原子接入，队列空则关闭本轮；无需每十分钟手动开窗。桌面关闭时拒绝唤起应用，不能把 worker 恢复说成桌面整体重启验收。
9. 原 RN observer 更新为文件快照/原生 follower 组合；仅该独立只读观察器被刷新，原 RN 队列 worker/MCP 消费 turn 不重启。
