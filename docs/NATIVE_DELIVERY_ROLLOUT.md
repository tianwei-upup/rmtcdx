# 手机正文直入的项目推广

2026-10-23：未加载历史会话、荣耀原生审批拒绝及 RN 历史会话复验通过后，按项目启用正文直入。当前策略覆盖全部已发现本机项目，并自动覆盖后续发现的项目 / 会话。手机正文仍进入原 ID 的原生原子队列，不再为这些会话追加长篇领取说明。

本文更新 `NATIVE_DIRECT_BODY_VALIDATION.md` / `NATIVE_QUEUE_WAKE_VALIDATION.md` 中“仅 acceptance 启用”的历史范围。全项目策略已启用，不代表对全部历史会话逐一进行了真机发送。

## 迁移与执行

手机 → ECS 业务意图 → 本机持久 Inbox → 原生队列原子追加正文 → 无正文 wake → 原生桌面执行 → 原生增量 / 工具 / 审批与最终结果投影。

- 新旧会话使用相同路径；原生会话 ID、上下文、模型及桌面沙箱 / 审批配置保持原值。未归档会话沿用桌面权限，归档只能读取；目录不存在时只能读取历史。
- `NativeDeliveryManager` 按项目选择路径，运行中刷新发现目录。推广策略最终为 `allProjects: true`，后续发现项目无需维护本轮固定名单。RN 既有 15 个队列仍由 RN 服务持有，其余由个人服务持有，不搬迁 Inbox。
- 不为数百条历史记录预先创建 Inbox 或加载原生 owner。已存在队列自动检查，其他会话在首次使用时建立队列、检查并迁移。仅完整初始化元记录的空会话可作为新空会话处理；缺失或无法确定完成状态的记录不能据此认定空闲。
- `.jsonl.zst` 旧历史在内存中只读解压，压缩输入上限 64 MiB、输出上限 512 MiB，只解析身份头和最多 1 MiB 结尾。同文件代次只缓存布尔结果，不缓存正文；仍检查项目 / cwd / binding、归档、原生队列和文件身份。原生新建 live 文件后立即以它为准，不沿用旧压缩文件的空闲证明。损坏、截断或无确切完成事件仍等待，不改写原历史。
- 本机事务持久化 `native_delivery` 的项目 / cwd / binding。只在原生空闲、无旧消费者、无已领取 / 未知任务及无启用待命策略时迁移。活跃原生回合等待自然结束，不发送插话或中断。旧消费者仍可完成原租约，不强制回收。
- 迁移选中的会话先关闭旧激活路径。旧 receiver 在异步读取后、原子追加前再次检查归属；数据库触发器拒绝旧消费者重新开启或抢占任务。手机排队正文不会被两个执行器消费。
- 保留稳定 client_id、原子入队、持久回执、原生 turn 关联、重复意图复用和冲突拒绝。未知结果不重放，队列项消失不当作执行完成。项目 / cwd / binding 变化拒绝续写，不用同 cwd 扩权。
- 当前安装 CLI `0.163.0-alpha.11.1`；wake 仍校验 bootstrap / main 固定哈希，未知安装版本拒绝新原生写入。未修改签名应用、未使用第二模型执行器或生产 start / steer / interrupt。

## 部署与保护

先只启用专用项目，完成未加载测试后启用 RN 并复验，随后逐项目更新策略，最终允许后续发现项目自动采用新路径。更新前直接读取各 Inbox 确认无活跃手机消费者或 queued / leased / unknown 任务；只更新个人 / RN 接收服务和 RN 历史 publisher，停止并禁用自动启动已被替代的 RN 旧启动 receiver。

本轮还修复服务停止窗口：quiesce 后立即停止 ECS agent 新领取；已经发出的 claim / ACK 若晚到且尚未执行，持久化明确拒绝，不误标“执行结果未知”；已执行结果及既有回执继续回传。5 项真实 HTTP / TaskBoard / Inbox 回归覆盖晚到 claim、晚到 ACK、执行结果晚到和旧成功 / 未知回执。native 恢复因绑定变化受阻时，也拒绝伪装取消已预留原生任务。

RN 初次服务启动遇到旧 standby 名单包含已归档成员而拒绝配置。新模式不再为这些成员构造旧 standby 配置，保留数据库中的实际旧租约 / 待命状态；核对其余队列为空后恢复服务，没有重放消息。

桌面 PID 89980、app-server 90668、exec-server 94001，独立 acceptance worker 64464 / publisher 96150 的 PID 和启动时间保持。没有重启桌面、全局 MCP 或 ECS，也没有向其他活跃会话发送消息、改其设置或中断回合。活跃原生会话的迁移延后属于预期保护。
