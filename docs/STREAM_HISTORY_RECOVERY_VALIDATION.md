# 中间输出保序与首次历史加载恢复验收

日期：2026-10-23。状态：本轮三条原始历史会话样本通过；不代表所有网络条件下固定首段延迟。

## 修复与根因

- 队列发布器只有 dirty 标记，上传等待期间的新状态被覆盖。阻塞上传回归实际复现 `[0,1,2,3] → [0,3]`；现按变化捕获不可变快照，保序发布，回执不明重试同一投影 revision。此重试不涉及业务消息或审批。待传投影只驻留内存，常规上限 64 份 / 8 MiB，长时间积压时保留在途头和最新状态，并记录 backpressure；不能保证长期离线期间逐段回放。
- 首次历史 GET 失败或返回不可用后缺少主动恢复；现添加单飞、500ms 至 5s 退避、分页失败重读和关闭取消。401/403/404 不自动重试，不发布未完成的分页前缀，旧 epoch 不恢复审批。
- 真机抓到离线历史读取→相同 desktop.reset→立即再读的循环，约 25 秒 315 次历史请求。相同 reset 去重；恢复可用后清除去重键，保证同 revision 再次离线仍立即禁用审批。
- 发现链路每次核对都全目录扫描，本机十次检查约 532ms；现只在桌面元数据、SQLite 主库或 WAL 的 inode/大小/纳秒 mtime/ctime 变化时重新发现。显式目录刷新仍强制发现；每次仍直接读精确会话行、归档状态与 cwd 可用性。基准约 4.7ms / 十次，属于本机样本，不是通用性能承诺。
