# 本机新增项目 / 会话持续接入验收

2026-10-22，用户授权后续新增的本机 Codex 项目和会话自动接入；归档仅查看，未归档沿用该桌面会话的沙箱、命令和人工审批权限。已更新现有 ECS 与个人项目 LaunchAgent，未重启 Codex 桌面，未热加载全局 MCP，未向其他活跃会话发送验收消息。

## 使用

电脑保持开机联网，在 Codex 正常添加本机项目、创建会话；APK 的项目 / 会话列表会自动更新，无需维护固定 ID 名单或每十分钟重新开启窗口。默认列表、搜索结果和项目会话数量只包含未归档会话；启动时保存的会话若已归档，优先恢复同项目的正常会话，没有时再选择其他正常会话。只有归档会话的项目显示空状态，不自动打开归档历史。首次接收按原 ID 原子入队，忙时由 Codex 排队执行。空队列结束本轮；后续手机消息由常驻服务再次接入原会话。既有 RN 长期待命消费者保持原样。

APK 仍使用当前 0.4.1 安装包和默认 ECS 地址；本次更新为服务和远程页面，无需重新安装主 APK。已经打开旧网页的手机需首次刷新以加载新版页面；荣耀已加载并验证新版。

## 实现与边界

- `PersonalScope.manifest.discovery = local-projects` 是本机人工授权开关；每次关键操作重新读取本机原生归属。兼容旧 `local-projects` / `thread-project-assignments`，以及原生 SQLite `projects` / `project_roots` / `threads.project_id`。原生项目迁移按桌面显式 alias 保留既有公开项目 ID；新原生项目使用自身 ID，不按共享 cwd 合并。会话名称优先读取新版 `threads.name`，兼容旧 `title`。
- 个人项目服务约每 2 秒发现目录变化；已配对且被 ECS 显式允许 `autoDiscover` 的电脑才可发布自己的精确项目 / 会话目录。版本 CAS、同版本幂等、跨设备 ID 冲突拒绝。目录仅保存元数据，正文仍只在本机及 ECS RAM 投影中。
- 原 RN 15 个会话及独立 acceptance 仍路由到原进程，本次没有迁移、重启或重建其 Inbox。新增会话使用个人项目服务独立、按需创建的 Inbox。发现目录变化不会重建已有消费者或重放 unknown 任务。
- ECS 保存最近目录；服务恢复后必须收到电脑的目录确认，才允许新的个人项目写入。目录确认超过 10 秒失效；新消息携带项目 / cwd 的不可逆绑定摘要。归档、移除、缺目录或上下文变化会在 ECS 和本机再校验；已入队消息不能跨项目 / cwd 自动执行。有未完成任务时上下文变化会暂停接纳，先取消或核对已有结果。
- 桌面历史 / 工具与人工审批的授权目录同步更新；受影响的旧视图和审批意图失效，其他视图与队列保持。新增成员只允许当前桌面权限，手机不会自动批准，也不会获得更高权限。
- APK 通过独立目录 SSE 收到变化，5 秒轻量版本查询补漏；启动目录 GET 的网络失败最多重试 3 次、单次 8 秒，登录失效不重试，不涉及消息写入重放；更新列表不刷新 WebView、不清空草稿、不提交模型任务。目录发现周期不等于模型响应时延保证。
- 旧缓存 MCP 明确拒绝新 ID 且尚未领取任务时，V2 接入提示允许普通命令工具调用受本轮原生身份约束的队列兼容入口。已持久化的 V1 接纳回执保留原提示字节，避免改协议导致原 ID 冲突或重放。
- 容量保护：最多 100 个本机项目、5000 个会话、单项目 1000 条；超过范围暂停发布并记录错误，不静默截断或扩大权限。
