# Codex 升级后手机消息不被领取的修复

2026-10-22。用户反馈 APK 发消息后一直显示“等待电脑开启接收”。本次没有重启 Codex 桌面、全局 MCP 或原有 RN 消费进程；仅更新无在途任务的独立接收服务与 ECS 静态资源。

## 根因与复现

- 目标为当前“评估同账户 Codex 接入方案”原会话。消息 `554d6c63-a6cb-4abe-8a9d-ffe6af2c6c9a` 已进入个人服务 Inbox，状态 `queued`、revision 1、没有 consumer；原生队列中尚无它的接纳控制消息。
- 桌面当前 CLI 为 `0.163.0-alpha.11.1`，个人服务与旧历史接收器仍只接受 `0.163.0-alpha.10.2`。版本检查发生在接纳之前，因此模型根本没有收到请求。
- 个人服务外层 `catch {}` 吞掉版本错误，心跳和目录仍在线；RN 历史接收器又把错误统一记成 `original_desktop_unavailable`，掩盖了真实原因。
- APK 将“无 active consumer”解释为需要手动开启；自动接入能力又只从历史投影读取，首次历史未就绪时也会错误显示该提示。
- 新增真实调用路径的回归：旧实现对 `.11.1` 执行只读历史加载时失败，错误为 `desktop_build_changed`。修复后该用例通过。

## 修复

1. `desktop-runtime.mjs` 统一精确版本与同用户桌面进程检查，明确支持 `.10.2`、`.11.1`。未知版本仍拒绝；没有改为宽泛版本范围，也没有启动第二个 CLI。
2. 原生 SQLite 结构与迁移继续在每次实际追加前校验。本机 `.11.1` 的结构指纹仍为 `b1d0caf9abeec1744bc84b2373a312e0c09bdeb3c808c9bf8b0fcc5dcc7e24c5`，两条迁移成功且 checksum 匹配。
3. 共用接收 tick 将前置检查和单会话错误明确发布到对应 receiver 状态；个人服务记录实际版本、错误码、恢复事件，并限频重复错误。单个会话错误不会阻断其他会话。
4. 个人项目的自动接纳能力来自已鉴权目录，即使大历史未加载也不要求手工开窗。归档、缺目录和禁写仍排除；旧队列仍需要显式能力。排队提示改为“已排队，等待原会话处理”。

## 真实验证

| 路径 | 结果 | 边界 |
| --- | --- | --- |
| 原排队消息 | 当前原生 turn 经 MCP 领取原“你好”消息，回复并完成；荣耀实际页面可见，真正刷新后仍恢复；最终原会话历史 available/complete 均为 true，显示“历史已同步 · 可直接发送” | 此条是恢复现有任务，不能用它冒充自动唤醒验证 |
| 固定 acceptance | 仅添加一条只读回声任务，经新版 guard、原子原生队列和原会话执行，返回 `DESKTOP_11_RECEIVE_OK`，consumer 正常关闭 | 一次定向接纳探针，不是常驻个人队列证明 |
| 个人项目专用会话 | 服务更新后经 ECS 入队，未手动开窗或补发原生命令，常驻服务自行接纳并完成 `PERSONAL_11_AUTORECEIVE_OK`，原 ID、consumer closed、receiver idle | 验证的是个人服务实际自动链路，不是全部会话逐一执行 |
| 防护回归 | 未知版本、缺少/重复/其他用户桌面、schema 漂移均拒绝；同意图保持原接纳 ID，单会话失败不阻塞其他接收器 | 不取消版本和归属门禁 |
| 构建 | companion build、103/103 测试；business build、94/94 测试通过 | 当前工作区包含既有登录限流改动，不是本次独立暂存树计数 |

确认个人队列无 active/stopping consumer、无 leased/unknown 后，对个人服务及两个独立历史接收器发送定向 SIGTERM，由原 LaunchAgent 恢复。原 RN/test 队列 worker 仍为 PID 3368/3369；桌面 PID 12549 和 CLI PID 13219/14121 保持原启动时间。没有更改队列授权、沙箱、Hook 信任或用户连接配置。

ECS 仅对 `queue-state.mjs`、`queue-app.js` 的 web/dist 做 SHA 比对、备份、语法检查与原子替换，按依赖先模块后调用者发布；业务 PID 72522 未变。服务器没有安装或运行 Codex。没有重装主 APK；荣耀当前会话与登录保留。

## 说明与后续

- 同一桌面会话忙碌时，手机消息仍须等该原生 turn 结束后排队处理，不能通过 steer/interrupt 提前插入。
- 大历史独立投影在过程中出现网络超时，最终荣耀刷新恢复、历史 available/complete 均为 true，渲染 1484 条原生项；这是该会话的本次样本，不作为固定加载时延保证。
- 后续未知 CLI 版本仍按保护策略拒绝写入，需要先验证实际结构、专用原 ID 接纳与领取，再增加精确兼容项。
- 详细证据位于忽略目录 `.runtime/receive-debug-20261022/`，不提交凭据、租约 token 或完整历史；原有无关改动保留。
