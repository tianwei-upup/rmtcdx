## 实现与恢复

`project-queue.mjs` 通过独立 `InboxService` 为每个原会话建立自己的 SQLite 队列、消费窗口、租约、取消版本和审计。领取绑定实际 MCP metadata 的 thread/turn；手机不能指定消费 turn、开启窗口或领取别的会话。每次操作重新核对桌面项目显式归属，移出项目后立即拒绝，新增项目归属不能扩大固定授权名单。

本地常驻 worker `scripts/start-project-queue-agent.mjs` 拥有队列及私有 socket；MCP 是连接此 socket 的 stdio 前端。worker 不需要桌面 pipe，也不创建 Codex/app-server。桌面会话结束后队列仍可接纳消息。worker 重启将已领取任务标为 unknown、关闭瞬时窗口，不重放；未知结果继续阻塞该会话，其他会话不受影响。显式启用的长期意图会保留，同一个仍在运行的原生 turn 可通过 resume 续窗；有限模式和已暂停的待命不会自行恢复，完整桌面退出仍不能自动唤醒。

本机私有配置 `.runtime/project-queue-rn/{scope,config}.json`；运行状态与队列在其 `run/`。LaunchAgent 为 `com.liutw.rmtcdx.rn-ui-queue`。RN 目录仅新增本机 `.codex/config.toml`，配置 `rmtcdx_project_queue`；同目录其他命名项目调用工具时会被身份白名单拒绝。本次没有修改 RN 业务源码。

ECS 沿用原业务服务和 HTTPS，授权文件仍为 `/etc/rmtagt-business/queue-scope.json`，新增 `mode=project-readonly`。服务器、worker 和 MCP 同时校验范围。旧云端元数据从退役执行器迁移时，只允许显式授权且项目 ID 一致的会话重新登记，其他冲突仍拒绝。旧专用测试 worker 已停止并在 launchctl 中禁用，原 plist 和私有数据保留；没有停止桌面 MCP 或其他项目执行器。
