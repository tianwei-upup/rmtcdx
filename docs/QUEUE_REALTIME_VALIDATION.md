100 次传输验收均在领取前取消，没有执行模型任务。随后开启专用原生窗口，处理 8 条回显、1 条真实分段回答、1 条处理中取消、1 条最终回显：10 条 completed、1 条 cancelled。两次公开累计分段在 leased 状态实际显示，最终显示完整结果；不是模拟打字。处理中取消的请求显示仍为亚秒级，原生模型确认取消耗时 **6.72 s（仅 1 个样本）**，不代表立即中断整个桌面 turn。

手机时长从生成本次提交 intent 到 DOM 应用后的 requestAnimationFrame 观测，用同一页面的 performance.now() 计算；不包含用户输入时间、滚动时间和开启桌面窗口之前的等待。服务端观测只记录 ID、阶段、时长及 sse/poll，不记录正文。Mac 各阶段由同机审计时间计算，不跨设备时钟相减。首段指标包含单段完成答案；它不是原生 token 首字延迟。

这些是前台、单设备、顺序请求、已开启领取窗口的实测结果，10 个模型样本的 P95 接近最大值，不是长期服务等级保证。复杂任务、多消息排队、弱网、后台 WebView、机器休眠和模型繁忙仍会增加耗时。此前单条回显 35.851 s 的记录仅用于定位旧链路问题，不作为同条件压测对照。

## 实现

- 读写分离：队列入队、取消和停止有独立领取通道，目录查询不能阻塞写入；心跳维护不阻塞下一次接纳。
- 推送：本机变更约 20 ms 合并后通过独立 HTTPS publisher 发送，ECS 仅在内存保存正文投影，SSE 推送变化。正常推送时网页没有周期性状态读取；断线时从直接缓存端点恢复，避免制造 queue.status 业务任务。
- 确认：收到本机持久化回执即可结束手机提交等待，不再等待交付任务的慢响应。旧请求完成不能清除后续新 intent；发送响应丢失后按原 intent 核对，不重复发送。
- 模型：`rmt_queue_listen` 合并开窗和首次领取；`rmt_queue_reply` 原子检查取消并完成或 ack_cancel，再等待下一条；长回答通过 `rmt_queue_progress` 发布真实累计公开文本。相比逐条 checkpoint / complete / take，减少模型轮次。
- 恢复：publisher epoch / revision 防止旧进程覆盖新投影；SSE 重连读取最新快照；1 s worker 心跳、8 s 过期门槛和 2 s SSE 健康通知标记失联。worker 重启仍将未决租约标为 unknown，不能重放。成员移出授权项目时，下一次成员心跳清除该会话缓存并拒绝后续投影。
- 超时：默认 long poll 25 s，兼容真实项目已有的 30 s MCP 工具超时；最多 60 s 只用于已配置更长超时的前端。没有重载真实项目中已运行的 MCP 前端，也没有修改该项目的本机 MCP 配置。

## 使用

APK 继续使用 **0.4.0**，无需安装新的主 APK；本轮生产改动在网页、ECS 与 Mac worker。主机仍为 `https://47.95.141.18`，选择 Mac 后刷新网页。应显示“电脑在线 · 实时同步”。ECS 服务更新会使已有网页登录失效，重新输入原访问密码即可；任务状态从电脑恢复。

先在目标桌面会话明确要求开启只读领取窗口，再从手机发送。可在正常使用该会话时发出下面这条指令：

> 仅当前会话，开启 10 分钟、最多 20 条的只读手机队列领取窗口。优先使用 rmt_queue_listen；逐条用 rmt_queue_reply 原子回传并领取下一条，waitMs=25000；next 为 job 时直接处理。长回答用 rmt_queue_progress 发送真实公开分段，取消时原子确认。只做当前上下文问答和计算，不运行命令、不读写文件、不访问网络或设备、不使用凭据、不影响其他会话。额度或时间到期后停止，不自动重开。

当前已加载的旧 MCP 前端可能仍只有 open / checkpoint / complete / take；它们继续兼容，但不会自动获得合并工具带来的模型延迟收益。新工具在会话下一次正常加载 MCP 时生效，不通过重启桌面或打断活跃 turn 强制加载；若工具未加载，保持排队，不走 native 写入或 shell 兜底。**没有领取窗口时仍只排队，不能由手机自动唤醒桌面会话。**

完整旧桌面聊天记录尚未投影到队列页面。手机消息仍在同一桌面 turn 中由 MCP 消费，不等同于每条生成一个原生桌面 turn。任意代码执行、写项目、后台自动开窗及其他项目访问均不在本轮开放范围。
